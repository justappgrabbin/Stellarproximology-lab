# Modelmaker private chat

A new chat interface for the existing Modelmaker and Klein learning assembly.
The old SynthAi/SynthAI2 interfaces are not loaded. No external AI API key is
required. The app binds to 127.0.0.1 and is intended for one private owner.
Browser session separation is not a substitute for multi-user authentication.

## Run

Requires Python 3.11+ and Node 22+ (Node 24 also works).

```sh
python -m venv .venv
.venv/bin/pip install torch --index-url https://download.pytorch.org/whl/cpu
.venv/bin/pip install -r requirements.txt
.venv/bin/python -m assembly.desktop_server
```

Open http://127.0.0.1:7860. On Windows, use the virtual environment's
Scripts/python.exe and Scripts/pip.exe equivalents.

- **Install coding model (CPU)** downloads the pinned public
  `Qwen/Qwen2.5-Coder-0.5B-Instruct` checkpoint (about 1 GB) and activates it
  locally. It uses Apache-2.0 pretrained coding weights and Transformers' native
  Qwen implementation, with no remote model code or external inference API.
  Float32 CPU inference needs roughly 2 GB for weights plus working memory.
  This is a small code assistant; generated code still needs tests.
- **Upload books, projects or files** accepts any file type and retains the
  original privately. Upload limits are 128 MB per file, 512 MB per batch and
  32 files per batch. PDF/DOCX and UTF-8 source/text are indexed for retrieval.
  Images, audio, model weights and other binaries are retained without claiming
  their contents were understood. Text analysis is limited to 32 MB per file;
  scanned PDFs require OCR, which is not included.
- **ZIP/TAR project import** keeps the archive and extracts ordinary files into
  the private coding workspace. Paths, links, duplicate names and expanded size
  are checked before extraction. Limits: 1000 entries and 256 MB expanded total;
  nested archives are retained without recursive extraction. Environment files,
  Git internals and dependency folders are retained without indexing.
  Up to 16 text files per upload receive Klein study, each with up to 16 passages;
  remaining readable files are indexed and labeled awaiting study. Nothing is
  executed or installed during import. **Show uploaded files** lists contents,
  provides text viewing and downloads the original. Uploading does not train weights.
- **Chat** uses the loaded model's instruction/chat format, retrieved source
  passages and Klein analysis. Previously installed coding weights activate by
  default in new profiles, unless a different checkpoint is already selected.
  Without weights, responses are explicitly labeled source excerpts. The local
  context budget defaults to 4096 tokens; MODELMAKER_CONTEXT_LIMIT can change it
  within the checkpoint's own limit. Truncation is reported in response details.
- **Training** opens the repaired Modelmaker. Saved checkpoints persist beneath
  `.modelmaker/checkpoints`; training in this mounted UI activates the new model
  for the same browser session. Small scratch-trained models need substantial
  suitable training/evaluation before they can be expected to converse or code well.
- **Klein tools** exposes the 16 original implementations plus three scoped,
  source-based adapters. Availability is not evidence that every historical Klein
  capability has been fully implemented. See `vendor/KLEIN-SOURCE.json`.
- **Edit app** loads this application's own source, accepts exact source-fragment edits generated by the model or a
  manual replacement, and shows the exact diff. Applying a reviewed proposal checks
  Python/JavaScript syntax and runs project tests. Failed checks restore the old
  file. Backups are stored under `.modelmaker/self-edit-backups`. Refresh after
  interface edits; restart after Python edits. A coding-capable checkpoint is
  required for reliable generated edits; invalid model output never changes files.

All books, learned tool state, feedback, checkpoints, and edit backups are local
under `.modelmaker`, or `MODELMAKER_DATA` if configured. Never expose this private
server directly to the Internet. No models, books, or changes are auto-published.
Self-edits are code changes; test success does not guarantee their quality.

## Optional local MCP toolbox

```sh
.venv/bin/python computer/mcp_server.py
```

This is a real stdio MCP server exposing model inference, source study/retrieval,
Klein calls, watcher, clarification proposals and reviewed self-edits. It also
lists the reused computer hands. Computer actions default to proposals. It is
not automatically installed into this ChatGPT conversation. A compatible local
MCP client can launch that command; use `MODELMAKER_USER` to choose its local
profile. Its default profile is separate from browser sessions.

## Computer components retained for later assembly

Only backend modules were reused from pinned public commits:

- SynthAi `hover/synthia58-2026-09-27`, commit
  `d901b3e15aa7c99a32fbb15e9b0680d77243249b`: browser hand, Android hand,
  MCP tool broker, and their small dependency closure.
- SynthAI2 `build/embedded-linux-birth-candidate`, commit
  `7b28f9e70c9e400e4f50f402dc8766d47ea8a18e`: Linux command service.

Neither donor interface is used. The private chat does not launch a computer or
Android emulator. Android hands require an actual configured bridge. A future
public computer should use the user's Kimi Linux build from Drive, which has not
been integrated in this private-chat delivery. No public container was deployed.

## Verification

```sh
.venv/bin/python -m unittest discover -s tests -v
```

Tests exercise the actual CPU weight objective/update/reload, real Klein source
analysis and model routing, upload-to-retrieval, browser-session separation,
self-edit stale-file checks, and rollback after failed project checks.

## What this version is

This is a real local causal language model with external tools, not a complete
new operating system. Pretrained weights provide initial coding experience;
retrieval supplies uploaded material; Klein tools analyze and retain observed
language patterns; reviewed edits change the app's actual files. Book upload
and feedback memory do not silently change model weights. The existing scratch
training UI still builds GPT-2 checkpoints; it does not fine-tune Qwen weights.
It can be developed toward a future Synthia computer, but arbitrary program
execution and understanding every file format are separate capabilities.

Coding checkpoint verification used the actual downloaded Qwen weights on CPU:
its generated unique-in-order function passed three functional cases; it
proposed an exact source edit that passed the edited project's test; and the
chat interface produced a working addition function with Klein routing active.
The small model also gave an imprecise explanation in one source-backed reply,
so code checks and review remain necessary. These checks establish basic coding
functionality, not general autonomous programming competence.
